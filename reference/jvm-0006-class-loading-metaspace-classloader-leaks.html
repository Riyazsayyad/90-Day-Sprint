Class Loading & Metaspace Cheat Sheet

Phases, loaders, leaks

1. Loading Phases

  1. Loading — bytes → Metaspace metadata + Class mirror
  2. Linking — verify, prepare (static defaults), resolve
  3. Initialization — <clinit> static blocks + static field init

2. clinit Triggers

  • new Foo(), static field/method use
  • Class.forName("Foo") — initializes
  • Not: new Foo[10]
  • Parent clinit before child

3. Classloader Hierarchy

Bootstrap (null) → Platform → Application → Custom

Delegation: parent loads first (default)

Breaks: SPI (ServiceLoader), Spring fat JAR, OSGi/JPMS awareness

4. forName vs loadClass

API Init?
Class.forName(name) Yes
loadClass(name) No

5. Metaspace vs PermGen

  • Java 7−: PermGen in heap — MaxPermSize
  • Java 8+: Metaspace native — MaxMetaspaceSize
  • Same leak patterns — different OOM message

6. Classloader Leaks

  • Redeploy without JVM restart
  • ThreadLocal without remove() on pool threads
  • JDBC DriverManager registration
  • Long-lived threads / shutdown hooks with app classes
  • APM / Hibernate generated classes

7. Loader GC Condition

No strong refs to loader + all its Class objects + instances unreachable → Metaspace reclaimed.

8. Enterprise

  • K8s: new pod = fresh loaders
  • Dev hot-reload ≠ prod Metaspace profile
  • Agents add classes — monitor Metaspace
