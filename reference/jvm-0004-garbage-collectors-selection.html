Garbage Collectors & Selection Cheat Sheet

Collector families, G1/ZGC, when to pick

1. Collector Families

Collector Goal Flag (JDK 21)
Serial Tiny footprint UseSerialGC
Parallel Throughput UseParallelGC
CMS Legacy — removed —
G1 Balanced / default Default
ZGC Low pause, large heap UseZGC
Shenandoah Low pause concurrent UseShenandoahGC

2. G1 Essentials

  • Heap = equal regions (Eden / Survivor / Old / Humongous)
  • Young GC — evacuate Eden + Survivor
  • Mixed GC — Young + garbage-first Old regions
  • Humongous — object > ½ region → dedicated Old regions
  • MaxGCPauseMillis=200 — pause goal, not guarantee

3. ZGC / Shenandoah (concept)

  • ZGC — colored pointers, concurrent relocation, tiny STW phases
  • Shenandoah — concurrent compaction, forwarding pointers
  • Neither eliminates STW entirely
  • JDK 21: generational ZGC evolving — check release notes

4. Selection Matrix

  • API / p99 latency → G1 default; ZGC if Mixed GC spikes at large heap
  • Batch / throughput → Parallel
  • Small heap K8s pod → G1 + conservative -Xmx
  • 32 GB+ latency-sensitive → evaluate ZGC

5. When NOT to Tune

  1. Defaults until prod metrics exist
  2. Fix retention before collector swap
  3. Don't set -Xmx = container limit

6. K8s Spring Boot

  • -Xmx ≈ 50–75% of cgroup limit
  • Enable GC unified logging from day one
  • Alert Full GC count, correlate with APM p99
  • JVM opts in container env — not application.properties
