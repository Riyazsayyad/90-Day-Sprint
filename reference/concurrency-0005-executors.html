Executors Cheat Sheet

Pools, queues, rejection, Future, shutdown

1. Why Not Raw Threads

  • Reuse workers; bound concurrency + memory
  • Queue + rejection = backpressure
  • Central lifecycle (shutdown)

2. Types

  • Executor — execute(Runnable)
  • ExecutorService — submit, invokeAll, shutdown APIs
  • ThreadPoolExecutor — core, max, keepAlive, queue, factory, handler

3. TPE Submit Order

  1. threads < core → new worker
  2. queue has room → enqueue
  3. threads < max → new worker
  4. else → rejection handler

4. Runnable vs Callable / Future

  • Runnable — void; execute or submit
  • Callable<V> — result + checked exceptions
  • get() / get(timeout) — block; ExecutionException wraps failure
  • cancel(mayInterrupt) — isDone / isCancelled
  • execute — uncaught → handler; submit — stored until get

5. Queues

QueueNote
LinkedBlockingQueue unboundedFixed pool trap — heap growth
ArrayBlockingQueueBounded — prod default
SynchronousQueueHandoff — cached pool

6. Executors Factories (Traps)

  • newFixedThreadPool(n) — unbounded queue OOM
  • newCachedThreadPool() — unbounded threads
  • newSingleThreadExecutor() — serialized + unbounded queue
  • Prefer explicit ThreadPoolExecutor in prod

7. Rejection Policies

  • Abort — RejectedExecutionException (default)
  • CallerRuns — submitter runs task (backpressure)
  • Discard — silent drop
  • DiscardOldest — drop head, retry

8. Shutdown

  • shutdown() — no new tasks; finish queue
  • shutdownNow() — interrupt + return pending
  • awaitTermination(timeout) — wait for idle

9. Sizing

  • CPU-bound ≈ cores (+1)
  • I/O-bound ≈ cores × (1 + wait/compute) — tune with metrics
  • Separate pools per dependency class

10. Enterprise

  • Tomcat — bounded HTTP worker threads
  • Spring @Async — configure ThreadPoolTaskExecutor; avoid per-task threads
  • Metrics: queue depth, active, rejected
  • ForkJoinPool.commonPool — parallel streams; no blocking I/O

11. Interview One-Liners

  • Queue between core and max — type picks failure mode
  • Fixed factory ≠ bounded — queue is unbounded
  • CallerRuns on HTTP thread = latency cascade
  • Pool doesn't fix races — still need sync/locks
