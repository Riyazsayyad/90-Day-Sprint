Concurrent Collections & Atomics Cheat Sheet

CHM, CopyOnWrite, queues, atomics, CAS

1. Synchronized Wrappers — Traps

  • Per-method sync ≠ atomic compounds
  • Iterate inside synchronized(wrapper)
  • Coarse lock — poor read concurrency
  • Prefer CHM / j.u.c collections

2. ConcurrentHashMap (Java 8+)

  • Bins (not segments) + treeify at 8 nodes
  • Per-bin locking / CAS — parallel different bins
  • computeIfAbsent / merge — atomic compounds
  • size() approximate under concurrency
  • Iterators weakly consistent — no CME
  • No null keys or values

3. CopyOnWriteArrayList

  • Read lock-free; write = copy array + swap ref
  • Iterator = snapshot — no later writes visible
  • Win: rare writes, heavy iteration/listeners
  • Lose: frequent mutations — O(n) per write

4. BlockingQueue

TypeNote
ArrayBlockingQueueBounded, fixed memory
LinkedBlockingQueueBounded or unbounded heap growth
SynchronousQueueHandoff, zero capacity
  • put blocks when full; take when empty
  • offer / poll(timeout) — non-blocking variants

5. Atomics

  • AtomicInteger/Long/Reference — volatile + CAS
  • incrementAndGet, compareAndSet(expect, update)
  • CAS fail → retry loop (optimistic)
  • volatile alone ≠ i++ atomic
  • Multi-field invariant → lock or immutable snapshot
  • Hot counters → LongAdder

7. Enterprise Picks

  • Cache lazy load → CHM.computeIfAbsent (+ TTL lib if needed)
  • Metrics → LongAdder / AtomicLong
  • Listeners → CopyOnWriteArrayList
  • Pool handoff → bounded ArrayBlockingQueue
  • Spring mutable singleton state → CHM or immutable refs

8. Interview One-Liners

  • Sync map check-then-act without outer sync = bug
  • CHM loader in computeIfAbsent — keep fast, no reentrancy
  • CopyOnWrite ≠ concurrent queue
  • Atomics fix one variable RMW — not arbitrary invariants
