Diagnostics & Memory Leaks Cheat Sheet

Toolbox, incidents, leaks

1. Toolbox

Tool Answers
jps -l Java PIDs
jcmd Dump, GC histo, JFR, VM info
jstat -gc Live GC stats
jstack / Thread.print Thread dump
jmap -histo / heap dump Instance counts / full heap

2. Thread Dump States

  • BLOCKED — waiting for monitor (sync)
  • WAITING / TIMED_WAITING — park, wait, sleep
  • RUNNABLE — running or native I/O

3. Heap Dump

jcmd <pid> GC.heap_dump /tmp/heap.hprof
-XX:+HeapDumpOnOutOfMemoryError

MAT dominator tree — top retainers = leak suspects

4. Leak Patterns

  • Static unbounded collections
  • Unclosed resources
  • Listener registries
  • ThreadLocal no remove
  • Classloader leak (Metaspace)

5. Native / Direct

  • Direct buffer memory OOM — not -Xmx
  • Netty — release buffers
  • jcmd VM.native_memory summary

6. Profiling

  • CPU flame graph — wide = hot CPU
  • Allocation profile — who allocates → GC pressure
  • JFR — prod-safe events, analyze in JMC

7. Incident Flow

  1. Correlate APM timestamp
  2. GC logs — pauses? Full GC?
  3. Thread dump — I/O vs BLOCKED?
  4. Histogram / heap dump if retention
  5. One fix; keep logs

8. Signal → Tool

  • Deadlock / stuck threads → thread dump
  • Growing heap → histogram → dump → MAT
  • High CPU, quiet GC → CPU profile / JFR
  • Metaspace OOM → classloader (S06)
  • Pool rejected → thread dump + pool metrics
