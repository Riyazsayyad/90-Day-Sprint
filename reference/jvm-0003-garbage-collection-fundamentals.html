Garbage Collection Fundamentals Cheat Sheet

Reachability, phases, pauses, generations

1. Why GC

  • Automatic reclamation vs manual free/ leak risk
  • Trade-off: pauses + CPU vs safety + productivity

2. GC Roots

  • Thread stack locals
  • Static fields
  • JNI global refs
  • Monitor objects (threads blocked in sync)
  • JVM internals / class loaders

Alive = strong path from any root. Unreachable = eligible (not instant).

3. Reference Strengths — When Cleared

Type Collected
Strong While reachable
Soft Before OOM — memory pressure
Weak Next GC
Phantom After object memory freed — queue cleanup

4. GC Phases

  • Mark — find live objects from roots
  • Sweep — free dead space (may fragment)
  • Compact — move live, fix refs
  • Copy — move live to new region (Young gen)

5. STW vs Concurrent

  • STW — app threads paused at safepoint
  • Concurrent — GC + app overlap; some STW still
  • APIs care p99 pause; batch cares throughput

6. Minor vs Major / Full

  • Minor / Young GC — Eden + Survivors; frequent, short
  • Major — Old gen
  • Full — whole heap (+ often metadata); rare = investigate

7. Safepoints

Known bytecode stops where stacks are scannable. GC, dumps, some VM ops need them.

8. Classic Bugs

  • Static unbounded collections
  • ThreadLocal without remove()
  • Inner class holding outer ref
  • Premature promotion → Old fills → long pauses
