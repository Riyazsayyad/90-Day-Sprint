Collectors Deep Dive Cheat Sheet

Predefined Collectors, Custom Architecture, and Characteristics

1. Standard Collectors Reference

Collector Behavior Result Type
toList() Accumulates elements into a mutable List. List<T>
toSet() Accumulates elements into a mutable Set. Set<T>
toCollection(...) Accumulates elements into a custom collection factory (e.g. ArrayList::new). C extends Collection<T>
toMap(keyMapper, valueMapper) Maps elements to keys and values. Throws IllegalStateException on duplicates. Map<K, U>
toMap(key, val, mergeFn) Maps elements to keys and values, resolving duplicates with a merge function. Map<K, U>
joining(delimiter) Concatenates CharSequences in encounter order with delimiter. String
counting() Counts the number of elements (normally used as downstream). Long
summarizingInt(...) Calculates count, sum, min, max, average of map results. IntSummaryStatistics

2. Collector Architecture Components

  • Supplier (() -> A): Creates the mutable accumulation container (e.g. ArrayList::new).
  • Accumulator ((A, T) -> void): Folds the next element into the container (e.g. List::add).
  • Combiner ((A, A) -> A): Merges two container partitions (parallel streams only; e.g. (left, right) -> { left.addAll(right); return left; }).
  • Finisher (A -> R): Transforms the container to the final result (identity function if container is the result).
  • Characteristics: Configuration set declaring optimization flags:
    • CONCURRENT: Accumulator is concurrent-safe; engine can accumulate concurrently without synchronization (uses single container).
    • UNORDERED: Collection order does not matter.
    • IDENTITY_FINISH: Finisher is an identity function, cast is safe from A to R.

3. Grouping vs Partitioning

Feature groupingBy(...) partitioningBy(...)
Classifier Function Function<T, K> (Maps element to any key type K). Predicate<T> (Evaluates element to boolean).
Output Map Keys Dynamic keys based on classifier return values. Always exactly two keys: true and false.
Downstream defaults toList(). toList().

4. Downstream Collectors recipes

  • mapping(mapper, downstream): Applies mapper to elements before collecting (e.g. groupingBy(Task::getProject, mapping(Task::getName, toList()))).
  • filtering(predicate, downstream): Filters elements *at the point of collection* rather than in the stream pipeline (crucial to prevent empty key omission).
  • collectingAndThen(downstream, finisher): Wraps a collector and applies a final function to the result (e.g. converting list to unmodifiable list).
  • teeing(c1, c2, merger): Directs elements to two separate collectors, merging results with a function.

5. Custom Collector Template

Collector<String, StringBuilder, String> joiningWithUpper = Collector.of(
    StringBuilder::new,                               // supplier
    (sb, s) -> sb.append(s.toUpperCase()).append(","), // accumulator
    StringBuilder::append,                             // combiner
    StringBuilder::toString                            // finisher
);
