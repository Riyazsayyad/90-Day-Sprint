final Keyword Cheat Sheet

Variable Invariance, Devirtualization, and Constructor Chaining Rules

1. Scope & Behavior Matrix

Target Scope Rule & Compiler Enforcement Primary Purpose
Variable (Primitive) Value cannot be changed after initial assignment. Constant values, state integrity.
Variable (Reference) Heap address pointer cannot change. Referenced object is NOT locked. Pointer safety, sharing references.
Method Cannot be overridden by subclasses. Declared private final methods are not overridden but hidden. Design locking, skeleton structure.
Class Cannot be extended/subclassed. All methods are implicitly final. Immutability, security protection.
Parameter Cannot be reassigned inside the method body. Prevent input mutations.

2. Definite Assignment of Blank final

  • Instance variables: Must be assigned exactly once in every constructor path or instance initializer block.
  • Static variables: Must be assigned exactly once in static initializer blocks or static declarations.
  • Local variables: Can be left unassigned upon declaration, but must be assigned exactly once before being read.

3. Compile-Time Constants (CTC) vs Runtime Constants

Feature Compile-Time Constants (CTC) Runtime final Variable
Declaration static final int MAX = 100; final double VAL = Math.random();
Resolution Resolved at compilation. Resolved at class initialization or runtime.
Bytecode Inlining Inlined directly as literals into client classes. Not inlined; resolved via field lookups (getstatic/getfield).
Class Loading Accessing CTC does NOT load or initialize the class. Accessing triggers standard class initialization.

4. Key JVM JIT Optimizations

1. Speculative Devirtualization

JVM maps dynamic method calls using a lookup table (vtable). When class/method is marked final, the lookup table is bypassed, transforming dynamic method lookup into direct calls.

2. Method Inlining

JIT replaces small method call instructions directly with the method body. Devirtualized final methods are ideal candidates, removing stack frame push/pop runtime overhead.

3. Constant Folding

Mathematical calculations involving constant fields (e.g. final int sec = 60; int min = sec * 60;) are pre-calculated to 3600 at compile-time.

5. Design Guidelines

  • String pool safety: java.lang.String is final to preserve integrity, caching, hash codes, and protect dynamic class loaders from loading malicious subclass variations.
  • Spring Injection: Constructor injection using final variables ensures complete object configuration on load and makes units mock-friendly.
  • Defensive copying: When using final variables referencing mutable types (like java.util.Date or Lists), return clone values to preserve class encapsulation boundaries.

6. Quick Code Reference

public final class Configuration {
    // Compile-Time Constant (Inlined directly by compiler)
    public static final String API_VERSION = "v2.0"; 

    // Runtime final variable
    public final long creationTime;

    // constructor injection / blank final initialization
    public Configuration() {
        this.creationTime = System.currentTimeMillis();
    }
}
