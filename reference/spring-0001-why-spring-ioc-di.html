Why Spring — IoC & DI Cheat Sheet

Module 05 S01 · concepts before annotations

1. Manual wiring (baseline)

UserRepository repo = new UserRepository(dataSource);
UserService service = new UserService(repo);
UserController controller = new UserController(service);
  • Explicit, testable, no magic — scales poorly when graphs branch (envs, mocks, features).

2. IoC vs DI

Term Meaning
IoC Framework controls object creation & lifecycle — inversion of control flow.
DI Dependencies supplied from outside (constructor/setter/field) — one technique inside IoC.

3. Injection styles

Style Senior take
Constructor Preferred — required deps, immutable final, easy unit tests.
Setter Optional / reconfigurable deps only.
Field Avoid in app code — hides deps, hard to test without Spring.

4. Bean

  • Object whose lifecycle & wiring the Spring container manages.
  • Not every new — DTOs, entities, value objects often stay outside the container.

5. Layers & dependency direction

Controller → Service → Repository → Database
         (depends on interfaces upward)
  • Upper layers depend on abstractions owned by domain/service boundaries.
  • Repository interface in domain; JDBC impl in infra package.

6. DIP sketch

interface PaymentGateway { Receipt charge(Money m); }
class StripeGateway implements PaymentGateway { ... }
class CheckoutService {
  private final PaymentGateway gateway;
  CheckoutService(PaymentGateway gateway) { this.gateway = gateway; }
}

7. Spring > boilerplate

  • Lifecycle callbacks, profiles, conditional beans
  • AOP cross-cuts (transactions, security, metrics)
  • Test slices (@WebMvcTest, @DataJpaTest — later)
  • Boot: auto-config + embedded servers + actuator hooks

8. Misconceptions

  • Spring ≠ creates every object
  • new is not banned (builders, DTOs, domain events)
  • DI ≠ IoC (DI is how; IoC is who controls creation)

9. Boot startup (preview)

  1. main → SpringApplication.run
  2. Prepare environment (properties, profiles)
  3. Create ApplicationContext
  4. Register & process bean definitions
  5. Instantiate singleton beans, inject dependencies
  6. Run runners / start embedded web server

Detail: S02 (context), S05 (auto-config).

10. Interview traps

  • “Spring replaces OOP” — no, it orchestrates object graphs.
  • “@Autowired on field is fine” — works, but constructor + final is the senior default.
  • “IoC and DI are synonyms” — precision matters.
