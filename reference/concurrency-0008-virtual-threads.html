Virtual Threads Cheat Sheet

Java 21+ · carriers · pinning · when to use

1. Platform vs Virtual

  • Platform — 1:1 OS thread, expensive
  • Virtual — JVM lightweight Thread, cheap
  • Blocking I/O on VT unmounts from carrier
  • Thread.isVirtual()

2. Carriers

  • Few platform threads multiplex many VTs
  • Default scheduler ≈ ForkJoinPool (cores)
  • Unmount on blocking I/O / park

3. Create (Java 21+)

Thread.ofVirtual().start(runnable);
Executors.newVirtualThreadPerTaskExecutor();
Thread.ofVirtual().name("x-", 0).factory();
  • Per-task executor — no pool size / queue cap
  • Don't pool virtual threads

4. Pinning Traps

Pins carrierFix
synchronizedReentrantLock or shrink scope
Native / JNIMinimize; isolate
  • Debug: -Djdk.tracePinnedThreads=full
  • JFR: jdk.virtualThreadScheduler.pinning

5. When to Use

WorkloadPick
I/O-bound (HTTP, JDBC, RPC)Virtual threads
CPU-boundBounded platform pool ~ cores
Need backpressureSemaphore / queue — VT executor alone isn't enough

6. Structured Concurrency (preview)

  • StructuredTaskScope — parent/child lifecycle
  • Fail or deadline → cancel siblings
  • vs allOf — no orphan tasks

7. Compatibility

  • ThreadLocal — works; millions × fat TL = OOM
  • Prefer ScopedValue for request context
  • Interrupt — same as L1
  • Thread dumps list virtual threads

8. Enterprise

  • Spring Boot 3.2+: spring.threads.virtual.enabled=true
  • Audit pinning, ThreadLocal, synchronized
  • DB/HTTP pool limits still apply
  • CPU jobs → separate bounded platform pool

9. Interview One-Liners

  • VT ≠ faster CPU — cheaper blocking
  • synchronized pins; ReentrantLock doesn't
  • Per-task VT executor has no queue cap
  • Flip Spring YAML + audit deps — not free lunch
