CompletableFuture Cheat Sheet

Pipelines, compose, errors, timeouts

1. Why CF vs Future

  • Future — block on get, no chain/combine
  • CF — CompletionStage pipelines + manual complete

2. Create (pass Executor for I/O)

  • supplyAsync(Supplier, executor) → CF<U>
  • runAsync(Runnable, executor) → CF<Void>
  • One-arg = commonPool() — no blocking I/O

3. Chain

MethodRole
thenApplyMap T → U (sync stage)
thenAcceptConsume T
thenRunRun after, ignore value
thenComposeFlatMap — T → CF<U>
thenCombineMerge two CFs when both done
  • *Async variants — run on executor (default commonPool)
  • Async next step depends on async step → thenCompose not thenApply

4. Errors

  • exceptionally — recovery on failure only
  • handle(result, ex) — always; one non-null
  • whenComplete — side effect; doesn't transform
  • Failed stage skips normal thenApply

5. Combine

  • allOf(...) — all finish (check each for errors)
  • anyOf(...) — first wins; cancel losers if needed

6. Block

  • get() — checked ExecutionException
  • join() — unchecked CompletionException
  • Real cause: getCause()

7. Timeout (Java 9+)

  • orTimeout(d, unit) — exceptional timeout
  • completeOnTimeout(fallback, d, unit) — normal fallback
  • cancel(true) — interrupt if running

8. Enterprise

  • Fan-out parallel deps at top — don't serialize get
  • Bounded named ioExecutor for all supplyAsync
  • Spring @Async returning CF — configure real pool
  • Per-call handle + SLA timeouts for BFF
  • Don't get() on Tomcat thread under load

9. Interview One-Liners

  • thenCompose = flatMap; thenApply = map
  • allOf succeeds even if child failed — check before join
  • Blocking in sync thenApply blocks completion thread
  • CF ≠ reactive — thread-per-stage orchestration glue
