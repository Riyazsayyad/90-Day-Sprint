Heap Regions, TLAB & Object Layout Cheat Sheet

Generational map, allocation, physical layout

1. Generational Layout

  • Young — Eden + Survivor S0 + S1
  • Old (Tenured) — long-lived objects
  • Most objects die young → cheap Young GC

2. Object Journey

  1. new → Eden (TLAB)
  2. Unreachable → reclaimed in Young GC
  3. Survives → copied to other Survivor; age++
  4. Age ≥ threshold or Survivor full → Old
  5. Large object → may pre-tenure to Old

3. TLAB

  • Per-thread Eden slice
  • Bump-pointer allocation — no lock
  • Full → new TLAB or slow shared path
  • -XX:+UseTLAB (default on)

4. Object Layout (64-bit, compressed — typical)

Mark Word     8 bytes  (hash, GC age, lock state)
Klass ptr     4 bytes  (→ Metaspace metadata)
fields        (primitives + ref slots)
padding       (8-byte align)

Empty object ≈ 16 bytes (typical with compression)

5. Mark Word States

  • Normal — GC age, identity hash
  • Biased / thin / fat lock encoding
  • GC mark bits during collection

6. Compressed Oops

  • -XX:+UseCompressedOops — 4-byte heap refs
  • Default when heap ≤ ~32 GB
  • UseCompressedClassPointers — 4-byte Klass
  • >32 GB heap → often off → bigger objects

7. Arrays

  • Header + length field + elements
  • int[] — dense primitives
  • Integer[] — ref per slot + boxed objects

8. Enterprise Patterns

Pattern Gen
Request DTOs / JSON parse Young churn
Singletons / caches / pools Old
