JVM Runtime Architecture Cheat Sheet

Memory areas, prod mapping, OOM triage

1. JDK / JRE / JVM

  • JVM — the running process (interpreter, JIT, GC, threads)
  • JRE — JVM + runtime libraries (historical; now modular runtime)
  • JDK — JRE + dev tools (javac, jcmd, jmap)
  • Container sees one JVM process per typical Java service

2. Process → JVM → Threads

  • 1 OS process = 1 JVM (usual)
  • Many threads share heap + Metaspace
  • Each thread has private stack
  • Races = unsynchronized heap writes

3. Memory Areas

Area Scope Stores
Heap Shared Objects, arrays · -Xmx
Stack Per thread Frames, locals, ref slots · -Xss
Metaspace Shared Class metadata, statics · MaxMetaspaceSize
Code Cache Shared JIT native code
Direct / Native Process NIO buffers, Netty · MaxDirectMemorySize

4. What Lives Where

  • Local primitive → stack
  • Local reference → stack slot → object on heap
  • Instance field (any type) → inside heap object
  • static field → Metaspace (ref targets heap object)
  • Class bytecode / vtable → Metaspace
  • Array → always heap (reference may be on stack)

5. TLAB (preview)

  • Per-thread Eden slice — bump-pointer allocation
  • Avoids global lock on most new
  • Detail in S02

6. Safepoints & STW

  • Safepoint — bytecode location where thread can stop safely
  • Needed for GC roots, JIT, thread dumps
  • STW — all mutators paused at safepoints
  • Dump stacks = coherent safepoint snapshot

7. OOM Triage

Message Pool Fix direction
Java heap space Heap Leak / retention / paginate / -Xmx
Metaspace Class metadata Classloader leak / codegen
Direct buffer memory Off-heap direct Netty/NIO release / pool limits
unable to create native thread OS threads Bounded pools / VT / ulimit
Stack overflow Thread stack Fix recursion / depth

8. Container Headroom Rule

-Xmx ≠ cgroup limit. Leave 25–40% for Metaspace, stacks, Code Cache, direct memory, native GC overhead.
