JVM Flags, GC Logging & Tuning Cheat Sheet

Heap, Metaspace, logs, G1, OOM

1. Heap Flags

  • -Xms — initial heap
  • -Xmx — max heap (objects only)
  • Prod: Xms = Xmx
  • -XX:MaxRAMPercentage=50-75 — % of container RAM
  • -XX:InitialRAMPercentage — initial % match

2. Metaspace

  • Not in -Xmx
  • -XX:MaxMetaspaceSize=256m — fail-fast cap
  • Blows up: Spring, Hibernate agents, dynamic proxies, hot redeploy

3. GC Logging (JDK 9+)

-Xlog:gc*:file=/var/log/gc.log:utctime,level,tags:filecount=5,filesize=20M

Read each line for:

  • Cause — Young / Mixed / Full
  • before->after(capacity) — heap reclaim
  • NNNms — STW pause time

4. G1 Knobs (know meaning)

Flag Does
MaxGCPauseMillis Soft pause goal (default 200)
G1HeapRegionSize Region size 1–32 MB
InitiatingHeapOccupancyPercent IHOP — start concurrent mark %

5. Tuning Order

  1. Enable GC logs
  2. Load test / prod metrics
  3. Fix retention & allocation
  4. Heap/container ratio
  5. Collector / pause goal
  6. Individual G1 knobs last

6. OOM Map

Message Fix
Java heap space Dump, leak, paginate, -Xmx last
Metaspace Classloader / agents
unable to create native thread Pool bounds, -Xss, ulimit
Direct buffer memory Netty/NIO release
GC overhead limit exceeded Leak or heap too small for live set

7. StackOverflowError

Thread stack depth — recursion. Not heap. Fix code; -Xss is per-thread multiplier.

8. Docker Starter (2 GiB pod)

-XX:MaxRAMPercentage=50.0
-XX:MaxMetaspaceSize=256m
-XX:+HeapDumpOnOutOfMemoryError
-Xlog:gc*:file=/tmp/gc.log:utctime,level,tags
