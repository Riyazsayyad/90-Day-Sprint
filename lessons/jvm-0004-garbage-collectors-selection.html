Garbage Collectors & Selection

~35 minutes · ties to mission · builds on S03 GC Fundamentals, S01 Memory Map

Senior Interview Focus: Can you name the default collector on JDK 21, explain when G1 Mixed GC fires, and why you'd pick ZGC over Parallel for a latency-sensitive API — without reciting 40 flags? Can you defend "defaults + measure first" on a new Spring Boot service in Kubernetes? Collectors are a product choice tied to SLO, heap size, and JDK version — not a religion.

Primary sources: Oracle — Available Collectors (SE 21) · Oracle — G1 GC · Oracle — ZGC

1. Collector Families — Overview

S03 taught mark/copy/STW vocabulary. Each collector implements those phases differently.

Collector Goal Typical use JDK 21 status
Serial Single-threaded, small footprint Embedded, tiny heaps, client-style apps Available (-XX:+UseSerialGC)
Parallel (Throughput) Maximize GC throughput — parallel STW workers Batch jobs, ETL, offline compute — long pauses OK Available (-XX:+UseParallelGC)
CMS Concurrent Old gen (legacy low-latency attempt) Deprecated — know it existed, replaced by G1/ZGC Removed in modern JDKs
G1 (Garbage-First) Region-based, predictable pause target Default on server JDK 9+ for most heaps Default collector
ZGC Sub-ms to low-ms pauses, scalable heap Latency-sensitive APIs, large heaps, JDK 15+ prod-ready Available (-XX:+UseZGC); generational ZGC evolving
Shenandoah Concurrent compaction, low pause Similar niche to ZGC; OpenJDK / some vendors Available on supported builds (-XX:+UseShenandoahGC)
Interview one-liner: "CMS is legacy — if someone says they tune CMS in 2025, ask which JDK they're actually on."

2. G1 — Default Workhorse

G1 splits the heap into equal-sized regions (~1–32 MB, ergonomic). No fixed contiguous Young/Old layout — regions are labeled Eden, Survivor, or Old dynamically.

2.1 Key mechanics

  • Young GC: collect all Eden + Survivor regions — copying live objects to new regions. STW, usually short.
  • Concurrent marking: background phase tracks live data across Old regions between Young GCs.
  • Mixed GC: collects some Old regions (highest garbage first — "Garbage-First") along with Young. STW but bounded by pause target.
  • Humongous objects: larger than half a region → allocated in dedicated contiguous humongous regions in Old. Expensive; avoid huge single allocations when possible (S02).
G1 region map (simplified):

  [E][E][E][S][O][O][H][O][E][O]...
   Eden  Sur  Old Humongous

Young GC  → evacuate Eden+Survivor
Mixed GC  → Young + subset of Old regions (garbage-first)

2.2 Pause target

-XX:MaxGCPauseMillis=200 (default 200 ms) — goal, not guarantee. G1 adapts region collection set to try to stay near target. Tighter target → more frequent smaller collections → may reduce throughput.

When Mixed GC hurts p99: Old regions with moderate live data → evacuation pauses spike. Fix retention / humongous objects before chasing flags (S05).

3. ZGC & Shenandoah — Low-Latency Collectors

Both target pause times independent of heap size (within reason) — critical when heap is 16–64 GB+ and G1 Mixed GC pauses breach SLO.

3.1 ZGC (interview level)

  • Colored pointers — metadata bits in reference encode GC state; concurrent threads use load barriers to see correct object version.
  • Concurrent relocation — moves objects while app runs; short STW phases for root scanning / phase flip, not full heap copy.
  • Pauses often sub-millisecond to a few ms on typical configs.
  • JDK 21+: generational ZGC (improving young-object collection) — check release notes for your exact JDK; awareness matters in interviews.

3.2 Shenandoah (interview level)

  • Concurrent compaction — Brooks forwarding pointers let app threads read objects while they move.
  • Similar positioning: low pause, concurrent Old collection.
  • Availability depends on JDK distribution (common in OpenJDK builds; verify vendor image).
Senior trap: "ZGC uses no STW at all" — false. STW exists but is tiny; don't claim zero pauses.

4. Parallel GC — Throughput First

  • Young: parallel copying STW. Old: parallel mark-sweep-compact STW.
  • Maximizes application throughput (% time not in GC) on multi-core batch workers.
  • Pauses scale with heap + live set — seconds possible on large Old gen.
  • Pick when: offline jobs, report generation, no interactive SLA, plenty of cores, pauses scheduled off-peak.

5. Selection Matrix

Factor Favor Notes
Latency SLO (p99 < 100 ms) G1 default; ZGC/Shenandoah if Mixed GC spikes Measure pause distribution first
Throughput / batch Parallel GC Accept STW pauses; maximize jobs/hour
Heap < 4 GB, simple service G1 defaults usually fine Don't over-engineer collector choice
Heap 32 GB+ API Evaluate ZGC G1 Mixed GC pause can grow with heap
Container limit 512 MiB–2 GiB G1 + sensible -Xmx headroom ZGC has overhead at tiny heaps — verify benchmarks
JDK version JDK 17 LTS / 21 LTS CMS gone; ZGC production-ready 15+; know your vendor build
Humongous allocation pattern Fix allocation; then G1 or ZGC Large byte arrays bypass Eden benefits

6. When NOT to Tune

Senior discipline beats flag shopping:

  1. New service, no prod data — use JDK defaults (G1 on 21). Ship.
  2. No GC logs or metrics — tuning blind is guessing.
  3. Retention bug present — collector won't fix static Map leak (S03).
  4. Pause problem not proven — profile p99; maybe it's DB not GC.
  5. Copy-paste flags from blog — heap size, allocation rate, and JDK version differ.
Correct order: measure → fix code/retention → set heap/container ratio → then collector/flags if SLO still breached.

7. JDK 21+ Defaults & Migration Notes

  • Default collector: G1 (-XX:+UseG1GC implicit on server-class machines).
  • CMS: removed — migrate stories to G1 or ZGC.
  • Parallel: opt-in for throughput workloads; was default pre-Java 9.
  • ZGC: -XX:+UseZGC — strong for large low-latency heaps; generational mode improving young-gen efficiency (check JDK 21 release notes).
  • Container awareness: JDK 10+ respects cgroup memory/CPU for default heap ergonomics — still validate -Xmx vs limit manually.
  • Migration from Java 8: expect different GC log format (Unified JVM Logging — S05); G1 not Parallel; review pause profiles after upgrade.

8. Enterprise — Spring Boot on Kubernetes

8.1 Heap vs container memory

# Example — 1 GiB pod limit
JAVA_OPTS="-Xms512m -Xmx512m"   # heap only
# Leave ~256–400 MiB for Metaspace, threads, direct, native, Code Cache

Rule: -Xmx ≈ 50–75% of cgroup limit for typical Spring + Netty services — validate with docker stats / cgroup metrics, not theory alone.

8.2 GC logging in prod (awareness — parsing in S05)

Enable structured GC logs from day one on new services:

-Xlog:gc*,gc+age=trace,safepoint:file=/var/log/gc.log:utctime,level,pid,tags:filecount=5,filesize=20M
  • Correlate GC pause timestamps with APM p99 spikes.
  • Alert on Full GC frequency, not every Young GC.
  • Ship logs to centralized observability (ELK, Datadog, etc.) — flags only in S05.

8.3 Spring Boot specifics

  • Actuator + Micrometer: JVM memory gauges, GC pause metrics (if binder configured).
  • Virtual threads (Java 21): allocation pattern shifts — still G1 default; monitor Young GC rate.
  • Don't set exotic GC flags in application.properties — JVM opts belong in container env / entrypoint.

Out of scope: exhaustive flag catalog (S05), line-by-line log parsing (S05), classloader leaks (S06), async-profiler (S08).

9. Revision Notes

  • Serial — tiny; Parallel — throughput; CMS — legacy dead.
  • G1 — region-based default; Young + Mixed GC; humongous regions; pause goal.
  • ZGC / Shenandoah — concurrent low pause; colored pointers / forwarding (concept level).
  • Pick collector from SLO + heap + JDK — measure before tuning.
  • K8s: -Xmx < container limit; GC logs from day one.
  • JDK 21 default = G1; ZGC opt-in for latency at scale.

10. Reasoning Exercises

  1. Batch nightly job, 8 GB heap, 4 s GC pause acceptable at 2 AM. Collector?

    Answer

    Parallel GC — maximize throughput; pauses off-peak acceptable. G1/ZGC overhead not justified unless pause causes job overrun.

  2. API p99 120 ms SLO, 24 GB heap, G1 Mixed GC pauses 300 ms. Next step?

    Answer

    Measure allocation + retention first. If code clean, trial ZGC on JDK 21. Don't only tighten MaxGCPauseMillis — it's a goal not a cap.

  3. 512 MiB K8s pod, -Xmx480m. OOMKilled. GC issue?

    Answer

    Probably not GC algorithm — off-heap exceeded cgroup (S01). Lower -Xmx to ~60% of limit; check direct memory / thread stacks.

  4. Candidate says "we use CMS for low latency." Red flag?

    Answer

    Yes if on JDK 17+. CMS removed. Story may be stale or mislabeled — likely G1 or ZGC in practice. Probe JDK version and actual flags.

11. 6 Senior-Level MCQs

Option lengths matched to prevent visual hints.

  1. Q1: Default GC on JDK 21 server JVM?

    1. G1 Garbage-First collector.
    2. Parallel throughput collector.
    3. Concurrent Mark Sweep only.
    4. Serial single-thread collector.
    View Answer & Explanation

    Answer: A (G1 Garbage-First collector.)

    G1 is default since Java 9 on server-class machines. Parallel and ZGC are opt-in.

  2. Q2: G1 Mixed GC collects which regions?

    1. Young plus some Old regions.
    2. Only Eden on every cycle.
    3. Metaspace class metadata bytes.
    4. Entire heap every single time.
    View Answer & Explanation

    Answer: A (Young plus some Old regions.)

    Mixed GC reclaims garbage-heavy Old regions alongside Young evacuation — bounded by pause target.

  3. Q3: MaxGCPauseMillis on G1 guarantees what?

    1. Soft pause target not hard cap.
    2. Zero stop-the-world ever again.
    3. Heap cannot grow past value.
    4. Young gen size fixed in bytes.
    View Answer & Explanation

    Answer: A (Soft pause target not hard cap.)

    G1 uses the value to guide collection set sizing. Spikes still possible under pressure.

  4. Q4: ZGC primary interview-level mechanism?

    1. Colored pointers concurrent relocate.
    2. Only serial mark-sweep Old gen.
    3. Disables all safepoint pauses.
    4. Stores objects in Metaspace only.
    View Answer & Explanation

    Answer: A (Colored pointers concurrent relocate.)

    ZGC uses pointer metadata and load barriers for concurrent relocation with short STW phase changes.

  5. Q5: Best first step before changing collector?

    1. Measure GC pauses and retention.
    2. Copy random flags from blog post.
    3. Disable GC with experimental flag.
    4. Set Xmx equal container limit.
    View Answer & Explanation

    Answer: A (Measure GC pauses and retention.)

    Defaults are fine until data proves otherwise. Fix leaks and allocation before collector swaps.

  6. Q6: Humongous object in G1 means?

    1. Larger than half a G1 region.
    2. Any object in Eden TLAB slice.
    3. Static field in Metaspace block.
    4. Thread stack frame over one MB.
    View Answer & Explanation

    Answer: A (Larger than half a G1 region.)

    Humongous objects get dedicated Old regions — costly path; avoid if possible.
