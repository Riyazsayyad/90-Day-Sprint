AOP Proxies, JDK vs CGLIB & @Transactional Internals

~40 minutes · Module 05 Lesson 6 of 9 · critical interview lesson · builds on this/super, lifecycle / BPP

Senior Interview Focus: @Transactional does nothing unless the call enters the Spring proxy. Self-invocation this.save() skips the proxy — same trap as this.txMethod() in oop-0013. Can you draw Caller → Proxy → advice → target, pick JDK vs CGLIB, and explain REQUIRED vs REQUIRES_NEW without hand-waving “Spring handles it”?

Primary sources: Proxying Mechanisms · Transaction Management · Understanding the Spring Framework’s Declarative Transaction Implementation

1. Why Proxies

Cross-cutting: transactions, security, metrics. Keep them off the domain method body. Mechanism: wrap the bean with a proxy that runs advice then delegates to the target.

Spring AOP is proxy-based (runtime). Full AspectJ compile/load-time weaving is out of scope.

2. Vocabulary

Term Meaning
Target Your real OrderService instance
Proxy Object the container injects into other beans
Advice Code around the call (begin tx, log, …)
Join point A method execution (Spring AOP limitation)
Pointcut Which methods get advice (@Transactional is a shortcut)

3. Call Chain

Caller (Controller)
    │  orderService.place(cmd)   // reference is the PROXY
    ▼
┌──────────── Spring Proxy ────────────┐
│  TransactionInterceptor (advice)     │
│    begin / get tx                    │
│         │                            │
│         ▼                            │
│    target.place(cmd)                 │
│         │                            │
│    commit / rollback                 │
└──────────────────────────────────────┘

BeanPostProcessor (AbstractAutoProxyCreator) replaces the bean with the proxy after init (S02 after-BPP). Other beans receive the proxy reference.

4–6. JDK vs CGLIB

JDK dynamic proxy CGLIB subclass
How java.lang.reflect.Proxy implementing interfaces Runtime subclass of the target class
Needs Target implements an interface; callers use the interface Non-final class; intercept non-final public methods
Framework default If ≥1 interface → JDK If no interface → CGLIB
Boot default spring.aop.proxy-target-class=true → CGLIB even with interfaces

Must know: Spring Framework docs: interface → JDK. Spring Boot sets class proxies on by default so injecting the concrete class still hits the proxy. If you inject by interface only, both work. Mixing “I injected the class” + proxy-target-class=false → ClassCastException.

CGLIB proxy is created via Objenesis — constructor of the subclass is not a second business ctor call in normal JVMs.

7. final — Proxy Limits

  • Final class: CGLIB cannot subclass → proxy creation fails for class-based proxy.
  • Final method: CGLIB cannot override → no advice on that method (silent skip — deadly for @Transactional).
  • Private methods: never proxied. Package-private: unreliable across classloaders.

8–9. @Transactional Internals

enter proxy method
    │
    ▼
PlatformTransactionManager.getTransaction(def)
    │  REQUIRED: join existing or begin new
    ▼
target method
    │
    ├─ return normally → commit
    ├─ RuntimeException / Error → rollback (default)
    └─ checked Exception → commit unless rollbackFor=...

Default rollback: unchecked only. throws Exception that you catch-and-wrap as checked → commit unless rollbackFor = Exception.class. Must know.

Swallowed exception (catch (RuntimeException e) { log } without rethrow) → interceptor sees success → commit.

10. Propagation (Interview Pair)

Propagation If tx exists If none
REQUIRED (default) Join it Begin one
REQUIRES_NEW Suspend, begin nested independent tx, resume Begin one

REQUIRES_NEW: audit log that must save even if outer tx rolls back. Cost: extra connection, deadlock risk. Do not sprinkle.

Nice to know: NESTED uses savepoints (JDBC). NEVER / NOT_SUPPORTED / MANDATORY — name them if asked; don’t invent.

11. Transaction Boundaries

The boundary is the proxy method you entered. Repository calls inside that method join REQUIRED. HTTP filter is outside. @Transactional on controller works but is a smell (transaction includes JSON mapping). Prefer service layer.

Reactive @Transactional is a different stack (S09 caveat: WebFlux + blocking @Transactional on servlet model ≠ event-loop safe).

12–13. Self-Invocation

OrderService (target)
  place()                // no @Transactional
      this.charge()      // SAME this — no proxy — no tx
  @Transactional charge()

Caller → proxy.place() → target.place() → this.charge() never re-enters proxy. You studied this bypassing Spring AOP in this & super.

Fix: move charge to another bean (self-injection of the proxy, or TransactionTemplate). Not AopContext.currentProxy() in app code.

Controller → proxy.place()     // tx if @Transactional on place
OtherService → orderService.charge()  // goes through proxy ✓

14. Pitfall Checklist (@Transactional doesn’t work)

  1. Self-invocation / same class
  2. Method not public (or final + CGLIB)
  3. Bean not Spring-managed (new OrderService())
  4. Checked exception / swallowed exception
  5. Called from another thread without passing context (tx is thread-bound — thread)
  6. Wrong DataSource / no PlatformTransactionManager bean
  7. Long tx holding DB connections → pool exhaustion (S07)

15. readOnly = true

Hint to the manager / Hibernate flush skip. Not a hard SQL write ban. A save() inside readOnly may still write depending on provider. Don’t use it as security.

16. Realistic Sketch

@Service
public class OrderService {
  private final OrderRepository repo;
  private final PaymentGateway gateway;

  public OrderService(OrderRepository repo, PaymentGateway gateway) {
    this.repo = repo;
    this.gateway = gateway;
  }

  @Transactional
  public OrderId place(PlaceOrder cmd) {
    Order order = repo.save(Order.from(cmd));
    gateway.charge(order.total()); // if this throws RuntimeException → rollback save
    return order.id();
  }
}

Controller injects OrderService (proxy). One HTTP thread, one tx, one rollback story.

Production Relevance

Silent commit after caught exceptions. Self-invocation in “refactor extract method.” Final methods on @Transactional services after a record conversion. REQUIRES_NEW leaking connections under load.

Interview Articulation

“Declarative transactions are Spring AOP. The container injects a proxy; advice starts a transaction via PlatformTransactionManager, invokes the target, then commits or rolls back. Default rollback is runtime exceptions. this.foo() never hits the proxy, so @Transactional on foo is skipped. Boot class-proxies with CGLIB unless you turn that off; final methods then silently lose advice.”

Revision Notes

  • Advice runs only through the proxy.
  • Boot: CGLIB class proxy default.
  • Rollback: RuntimeException; set rollbackFor for checked.
  • REQUIRED join; REQUIRES_NEW suspend+new.
  • this.method() bypass; other bean OK.

Interview One-Liners

  • “If the call never entered the proxy, there was no transaction.”
  • “Catch without rethrow is a commit.”
  • “REQUIRES_NEW is a new connection story, not a flag of quality.”

Senior MCQs

  1. Q1: this.save() inside the same @Service?

    1. Bypasses the proxy — no @Transactional advice.
    2. Always starts REQUIRES_NEW automatically.
    3. CGLIB rewrites this to the proxy always.
    4. Fails compilation on Java 21.
    View Answer & Explanation

    Answer: A (Bypasses the proxy — no @Transactional advice.)

  2. Q2: Default rollback for throws Exception (checked)?

    1. Commit unless rollbackFor includes it.
    2. Always rollback like RuntimeException.
    3. Tomcat converts it to HTTP 204.
    4. Opens a second nested savepoint always.
    View Answer & Explanation

    Answer: A (Commit unless rollbackFor includes it.)

  3. Q3: Spring Boot AOP proxy default?

    1. Class-based CGLIB (proxy-target-class true).
    2. JDK proxies only, even without interfaces.
    3. No proxies — bytecode weaving required.
    4. Enum singletons replace all proxies.
    View Answer & Explanation

    Answer: A (Class-based CGLIB (proxy-target-class true).)

  4. Q4: REQUIRED when a tx already exists?

    1. Join the existing transaction.
    2. Always suspend and start another.
    3. Ignore @Transactional completely.
    4. Bind the tx to a new virtual thread.
    View Answer & Explanation

    Answer: A (Join the existing transaction.)

  5. Q5: final @Transactional method on a CGLIB proxy?

    1. Advice typically does not run.
    2. JDK proxy is used instead automatically.
    3. JVM rejects the class at verify time.
    4. readOnly becomes a hard SQL lock.
    View Answer & Explanation

    Answer: A (Advice typically does not run.)

  6. Q6: Catch RuntimeException, log, no rethrow?

    1. Interceptor commits — exception was swallowed.
    2. Rollback still happens via ThreadLocal.
    3. REQUIRES_NEW starts on the catch block.
    4. Actuator marks liveness DOWN.
    View Answer & Explanation

    Answer: A (Interceptor commits — exception was swallowed.)

  7. Q7: new OrderService(repo) inside a controller?

    1. Not a bean — no transactional proxy.
    2. Boot wraps every new automatically.
    3. Equals injecting the singleton proxy.
    4. Forces request scope on the repo.
    View Answer & Explanation

    Answer: A (Not a bean — no transactional proxy.)

  8. Q8: readOnly = true guarantees?

    1. A hint — not a hard write block.
    2. Database user is switched to SELECT.
    3. CGLIB cannot proxy the class.
    4. Propagation becomes NEVER always.
    View Answer & Explanation

    Answer: A (A hint — not a hard write block.)
