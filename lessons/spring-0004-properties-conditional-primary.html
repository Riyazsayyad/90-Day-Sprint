Properties, @Conditional & @Primary

~35 minutes · Module 05 Lesson 4 of 9 · builds on S03

Senior Interview Focus: Spring decides whether a bean exists with conditions, and which bean wins with type matching, @Primary, and @Qualifier. Can you debug NoSuchBeanDefinitionException vs NoUniqueBeanDefinitionException in 30 seconds? Auto-config (S05) is this lesson applied at classpath scale.

Primary sources: Externalized Configuration · Conditions (auto-config) · @Autowired

1. properties vs yml

Same Environment. YAML is nested and lists; .properties is flat keys. Pick one per app. Illegal YAML indentation is a silent wrong-value bug — treat as a parse incident.

2. Property Sources (High Level)

Boot builds an ordered Environment. Later sources win. Practical seniority: command line > env vars > profile-specific file > application.yml (simplified — full list is long; don’t recite 15 ranks unless asked).

Env vars: SPRING_DATASOURCE_URL maps to spring.datasource.url. K8s ConfigMap/Secret → env → Environment. Never commit secrets (S08).

3. @Value

public Pricing(@Value("${pricing.markup:1.0}") BigDecimal markup) { ... }

Pros: one-off. Cons: stringly typed, scattered keys, SpEL #{ } surprises, hard to validate a group. Prefer for truly single flags.

Nice to know: ${} is placeholder; #{} is SpEL — mixing them is a footgun.

4–6. @ConfigurationProperties

@ConfigurationProperties(prefix = "shop.payments")
public record PaymentsProps(
    @NotBlank String provider,
    Duration timeout
) {}

Boot 3: records work. Enable with @EnableConfigurationProperties(PaymentsProps.class) or @ConfigurationPropertiesScan. Bind types, not strings. Validate with @Validated + Jakarta constraints — fail at startup, not on first payment.

@Value @ConfigurationProperties
Typing Per field conversion Structured object / record
Validation Manual @Validated on the type
IDE metadata Weak spring-boot-configuration-processor
Use One key A config area (pool, payments, feature flags)

7. Profiles + Precedence Story

application.yml              markup: 1.0
application-prod.yml         markup: 1.2
ENV SHOP_PAYMENTS_TIMEOUT=5s
java -jar app.jar --shop.payments.provider=stripe

Prod file overlays default; env overlays file; CLI wins. Interview: tell a story, not a 20-row table.

8–11. Conditions — Why a Bean Exists

Must know: A Condition is evaluated against the ConditionContext (Environment, classloader, registry) before the bean is registered or created. False → no BeanDefinition (or skipped auto-config class).

Annotation True when
@Conditional Custom Condition.matches
@ConditionalOnProperty Property equals expected (or present)
@ConditionalOnClass Class on classpath (safe — uses class name string internally in auto-config)
@ConditionalOnMissingBean No user bean of that type/name yet
@ConditionalOnWebApplication Servlet or reactive web app type 
@Bean
@ConditionalOnProperty(name = "shop.payments.provider", havingValue = "stripe")
PaymentGateway stripeGateway(PaymentsProps props) {
  return new StripeGateway(props);
}

This is the seed of auto-config (S05): classpath + missing bean + property → create DataSource.

12–15. Multiple Beans Same Type

Need PaymentGateway
   candidates: stripeGateway, razorpayGateway
        │
        ├─ injection point has @Qualifier("stripeGateway") → that name
        ├─ field/param name matches bean name (fallback)
        ├─ @Primary on one candidate → that one
        └─ else NoUniqueBeanDefinitionException

public interface PaymentGateway { Receipt charge(Money m); }

@Service
@Primary
class StripePaymentService implements PaymentGateway { }

@Service
class RazorpayPaymentService implements PaymentGateway { }

@Service
class CheckoutService {
  CheckoutService(
      PaymentGateway defaultGw,                 // Stripe (@Primary)
      @Qualifier("razorpayPaymentService")
      PaymentGateway inrGw) { ... }
}

@Primary vs @Qualifier: Primary = default when type is unique-enough. Qualifier = this injection point wants a specific bean. Don’t use Primary as a silent override in a 6-implementations zoo — name them.

16. Startup Errors

Exception Means Debug
NoSuchBeanDefinitionException Zero candidates Scan (S03), profile, @Conditional* false, typo name
NoUniqueBeanDefinitionException Two+ candidates, no winner @Primary / @Qualifier / inject List<T>

Tools: --debug condition report (S05), /actuator/beans, /actuator/conditions (S08).

Decision Tree

Autowire type T
  0 beans? → NoSuchBean → scan / profile / condition / @Bean
  1 bean?  → inject it
  2+ beans?
       Qualifier / name match? → that bean
       @Primary unique? → primary
       else → NoUniqueBean

Production Relevance

Feature flags as @ConditionalOnProperty keep dead integrations off the classpath graph. A missing env var that should enable Stripe → NoSuchBean in prod only. Config validation at startup is cheaper than a 500 on checkout.

Interview Articulation

“Environment is an ordered set of property sources. I bind groups with @ConfigurationProperties and validate them. Conditions skip BeanDefinitions when a property or class is absent — that’s how auto-config backs off when I define my own DataSource. If two PaymentGateways exist, @Qualifier picks a site; @Primary picks the default; otherwise NoUniqueBeanDefinitionException.”

Senior MCQs

  1. Q1: Two PaymentGateway beans, no @Primary/@Qualifier?

    1. NoUniqueBeanDefinitionException at injection.
    2. Spring randomly picks one each request.
    3. Both are silently ignored forever.
    4. Tomcat converts them into filters.
    View Answer & Explanation

    Answer: A (NoUniqueBeanDefinitionException at injection.)

  2. Q2: @ConditionalOnProperty false. Result?

    1. Bean is not registered / not created.
    2. Bean is created then immediately destroyed.
    3. Bean becomes request-scoped automatically.
    4. Only field injection still works.
    View Answer & Explanation

    Answer: A (Bean is not registered / not created.)

  3. Q3: Prefer @ConfigurationProperties when?

    1. A group of related typed settings.
    2. You need SpEL inside SQL strings.
    3. The value is a local loop counter.
    4. You want to skip the Environment.
    View Answer & Explanation

    Answer: A (A group of related typed settings.)

  4. Q4: @Qualifier vs @Primary at one injection point?

    1. Qualifier wins for that parameter.
    2. Primary always overrides Qualifier.
    3. Both are ignored if types match.
    4. Causes Metaspace leaks in JDK 21.
    View Answer & Explanation

    Answer: A (Qualifier wins for that parameter.)

  5. Q5: NoSuchBeanDefinitionException first checks?

    1. Scan path, profile, conditions, bean name.
    2. Only whether Tomcat maxThreads is 200.
    3. Whether the class used synchronized.
    4. G1 vs ZGC collector selection only.
    View Answer & Explanation

    Answer: A (Scan path, profile, conditions, bean name.)

  6. Q6: @ConditionalOnMissingBean purpose in Boot?

    1. User @Bean makes auto-config back off.
    2. Deletes all beans of other types.
    3. Forces field injection on DataSource.
    4. Disables the Environment completely.
    View Answer & Explanation

    Answer: A (User @Bean makes auto-config back off.)
